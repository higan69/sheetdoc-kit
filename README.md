# SheetDoc CMS

GoogleスプレッドシートとGoogleドキュメントを「データ置き場」にして、静的HTML 1枚を更新し続けるための簡易CMSテンプレートです。サーバーもデータベースもビルドも不要で、編集はGoogleの画面だけ、公開はHTMLファイルを置くだけです。

## 目的

- **メンテナンスコスト低減** — サーバー側のプログラムが無いので、本体・プラグインの更新、セキュリティパッチ、データベースの管理が要りません。壊れる場所そのものが少ない
- **学習コスト低減** — 編集画面はGoogleスプレッドシート／ドキュメントそのもの。新しい管理画面の操作を覚える必要がありません
- **小回りがきく** — HTML 1枚なので、直したい所を直したい時にすぐ直せます。テーマやプラグインの作法に縛られません
- **小規模店舗に最適化** — お知らせ・メニュー・料金・営業日・アクセスという「店舗サイトの定番」に絞り、予約やECのような重い機能は外部サービスへのリンクで逃がす前提です

WordPressが「何でもできる代わりに、常に面倒を見続ける必要がある道具」だとすれば、こちらは「できることを絞る代わりに、ほぼ面倒を見なくて済む道具」を目指します。

## 設計原則：枯れた技術だけで作る

このパッケージの部品は、Googleスプレッドシート／ドキュメント、CSV、「ウェブに公開」、静的HTML——どれも新しくはない、いわゆる「枯れた」技術です。これは意図的な選択です。

学習コストの正体は「覚えなければならない新しい概念の数」です。枯れた技術は、その概念がすでに世の中に共有されています。スプレッドシートと文書は、公民館のパソコン教室で教わるような、利用者が「もう知っている」道具です。新しい管理画面、新しいアカウント、新しい作法を持ち込まないこと。それがこのパッケージの学習コスト低減の実体です。

枯れていることは、保守の面でも効きます。不具合の出方が知られていて、仕様が大きく変わらず、情報が豊富にある。最新であることの対価（更新への追従、想定外の故障）を払い続けない設計です。

## 機能は「依頼の類型」から決める

ブロックの顔ぶれは、場当たり的に足したものではありません。小規模サイトの制作で実際に繰り返し求められる依頼は、類型としてほぼ決まっています。

- 知らせる（お知らせ・緊急告知）→ `doc` / `alert`
- 一覧で見せる（料金表・番組表・上映情報）→ `sheet-table` / 専用描画
- 品目と価格（メニュー）→ `sheet-menu`
- 時間（営業時間・上映時間）→ `sheet-hours` / `sheet-screenings`
- 人（キャスト・スタッフ・推薦の声）→ `sheet-credits` / `sheet-quotes`
- 場所（アクセス）→ `map`
- 証拠（写真）→ `sheet-gallery`
- 次の行動（電話・予約・SNS）→ `links`

高度な機能（予約システム、EC、会員機能など）は、実際にはほとんど求められません。求められたとしても、その領域には専門の外部サービスがあり、勝負する場所ではありません。**類型に無い機能は作らず、外部リンクで逃がす。** これがこのパッケージの機能選定のルールです。新しいブロックを足すかどうかは「それは類型か」で判断します。

## 仕組み

```
編集者 ──入力──▶ Google Sheets（表データ） ──公開CSV──┐
編集者 ──入力──▶ Google Docs（文章）     ──公開HTML─┤
                                                    ▼
閲覧者 ──表示──▶ index.html（fetchで取得して表示）
```

- スプレッドシートは「ウェブに公開」でCSVとして取得します
- ドキュメントは「ウェブに公開」のHTMLを取得し、付属のスタイルシートを**そのブロックの中だけに閉じ込めて**反映します（複数ドキュメントでも衝突しません）
- このHTMLは静的ホスティング（GitHub Pages、Netlify、レンタルサーバーの静的領域など）ならどこにでも置けます。`file://` ではブラウザの制限で取得できないため、必ず http(s) で配信してください

## セットアップ

1. `index.html` をコピーして、置きたい場所に置く
2. 表示したい内容を用意する
   - **表や一覧** → スプレッドシートを作り、「ファイル → 共有 → ウェブに公開」でリンクを発行
   - **文章（お知らせ等）** → ドキュメントを作り、同様に「ウェブに公開」でリンクを発行
   - **画像を含むドキュメントは、共有設定も「リンクを知っている全員（閲覧者）」にしてください。**
     「ウェブに公開」と「共有」は別設定で、共有が「制限付き」だとドキュメント内の画像だけが
     ページに表示されません（文章は表示されます）。 groove の booking ドキュメントで実際に起きた不具合の原因です
   - どちらも公開ダイアログで「変更されたら自動的に再公開」をONにすると、編集がそのまま反映されます（反映まで数分かかる場合があります）
   - **スプレッドシートは、1ブロックにつき1ファイル**にしてください。理由は2つあります。①1つのファイルをタブ分けして複数ブロックから参照すると、取得が不安定になることが実地で確認されています（タブの公開URLまわりの挙動が安定しません）。②更新する人にとっても、「直したい欄＝開くファイル」が1対1で対応している方が分かりやすい。ファイルが増えても、ブロックごとに分ける方が確実で、迷いません
3. `index.html` の `<script>` 先頭にある `CONFIG` に、サイト名と各ブロックの `url` を貼る。ページ最上部に大きな写真（ヒーローイメージ）を出したい場合は `CONFIG.heroImage` に写真のURLを入れる（空なら出ない。どの業種のパターンでも使える）
4. 配信して確認する。`url` が空のブロックや、取得に失敗したブロックは自動で非表示になります

表の形式を間違えないために、`samples/` フォルダに店舗向け（メニュー・営業時間・写真）と映画向け（上映情報・クレジット・推薦コメント・ニュース）のサンプルCSVを同梱しています。スプレッドシートで「ファイル → インポート」から取り込めば、正しい列構成の表がそのまま作れます。

## 役割分担（大事な前提）

このパッケージは「全員が全部できる」ことを目指していません。役割を分けるのが前提です。

- **作る人（制作者）**：初期設定だけを行います。Google側の表と文書を作って公開し、`index.html` の `CONFIG` にURLを貼り、配信します
- **店主（運用者）**：HTMLは一生触りません。日々の更新はGoogleの表と文書を書き換えるだけです

店主向けには `manual_owner.md`（更新マニュアル）を同梱しています。専門用語を使わず、「開いて、書いて、閉じる」だけの手順にしてあります。引き渡しの際は、更新に使う表と文書を店主のブラウザにブックマークしてもらうところまでが作る人の仕事です。

表示側も「編集ミスで壊れない」ことを優先しています。

- 表の先頭に見出し行（「品名」「価格」など）が混ざっていても自動で読み飛ばす
- 空行は無視する
- お知らせ文書を空にすれば、お知らせ欄そのものが表示されなくなる（＝「消す」操作が直感どおりに効く）

想定する担当者は「初期設定〜公開までは、ある程度の知識のある人」「運用（日々の更新）は素人」です。設定までノーコード化する設計にはしていないので、CONFIGの編集は作る人の作業のままです。

## 引き渡しチェックリスト（作る人向け）

運用が素人である前提では、引き渡しの出来がそのまま運用の成否になります。最低限これだけは済ませてください。

- [ ] 表と文書の**所有者は店主側のGoogleアカウント**にする（作る人のアカウントで作った場合、オーナー移行か作り直しをする。ここを曖昧にすると、作る人が関われなくなった瞬間に詰む）
- [ ] 店主のアカウントに編集権限が付いていることを確認する
- [ ] 公開ダイアログで「変更されたら自動的に再公開」がONになっていることを確認する
- [ ] 店主のブラウザに、更新用の表と文書をブックマーク登録する（その場で一緒にやる）
- [ ] 店主の目の前で、実際に1回更新してもらう（お知らせを書く→反映を見る、まで）
- [ ] `manual_owner.md` の連絡先欄に名前と電話番号を書き、印刷して渡す

## ブロックの種類

`CONFIG.blocks` の配列に足す・並べ替えるだけでページ構成が変わります。

| type | 内容 | Google側の形式 |
|---|---|---|
| `doc` | リッチテキスト。太字・色・見出し・表・画像とスタイルを反映。本文にURLを文字列のまま書いても自動でリンクになる（ドキュメント側でリンクにしなくてよい） | ドキュメント（ウェブに公開） |
| `alert` | 緊急バナー。ドキュメントに書けば赤い帯で表示され、空にすれば消える。操作はお知らせと全く同じ（店舗なら臨時休業、放送局なら災害情報） | ドキュメント（ウェブに公開） |
| `sheet-table` | 1行目を見出しにした表 | スプレッドシート（ウェブに公開） |
| `sheet-list` | 1列目=見出し、2列目=本文の縦リスト | スプレッドシート（ウェブに公開） |
| `sheet-menu` | 店舗向け：品名・価格・説明を、点線リーダー付きのメニュー風に表示（見出し行なし） | スプレッドシート（ウェブに公開） |
| `sheet-hours` | 店舗向け：曜日・営業時間・備考。今日の曜日を自動で強調表示（見出し行なし） | スプレッドシート（ウェブに公開） |
| `sheet-gallery` | 店舗向け：画像URL・キャプションの写真グリッド。Googleドライブの共有リンクを貼っても表示できます（見出し行なし） | スプレッドシート（ウェブに公開） |
| `map` | 店舗向け：住所（`address`）からGoogleマップを埋め込み。APIキー不要。`url` を指定すると住所・備考をシート（項目／内容の2列）で編集できる | CONFIGに直接記入（シートも可） |
| `links` | 店舗向け：電話（`tel:`）・SNSなどのボタン群 | CONFIGに直接記入 |
| `sheet-links` | `links` のシート版：ラベル・URLの2列。ボタンの内容をシートで編集できる（見出し行OK） | スプレッドシート（ウェブに公開） |
| `hero` | 映画向け：ポスター画像＋タイトル＋キャッチ＋公開日。公開日（`date`）を入れると「公開まであと◯日」を自動表示 | CONFIGに直接記入 |
| `youtube` | 映画向け：予告編。サムネイル表示→クリックで読み込む軽量埋め込み | CONFIGに直接記入 |
| `sheet-screenings` | 映画向け：上映情報（日付・劇場・時間・備考・URL）。終了した上映は予定欄から自動で消え、本日分を強調。月見出し付きで、初期表示は10件・残りは「もっと見る」で開く。終了分は欄末尾の「過去の上映を見る」から新しい順に遡れる（初期20件＋「もっと見る」）。5列目にURLを入れると、その行に「詳しく見る」ボタンが出る（終了分にも出る）。日付が読めない行（「近日」など）は告知として残る（見出し行なし） | スプレッドシート（ウェブに公開） |
| `sheet-credits` | 映画向け：キャスト＆スタッフ（名前・役名/担当・プロフィール）（見出し行なし） | スプレッドシート（ウェブに公開） |
| `sheet-quotes` | 映画向け：推薦コメント（推薦文・推薦者名・肩書き）（見出し行なし） | スプレッドシート（ウェブに公開） |
| `sheet-news` | 映画向け：ニュース（日付・見出し・リンクURL）。新しい順に自動で並び、月見出し付き。初期表示は10件・残りは「もっと見る」で開く（見出し行なし） | スプレッドシート（ウェブに公開） |
| `sheet-events` | ライブハウス向け：イベント日程（日付・イベント名・出演者・時間・料金・備考）。終了分は予定欄から自動で消え、本日分を強調。月見出し付きで、初期表示は10件・残りは「もっと見る」で開く（見出し行があっても自動で読み飛ばす。見出しの文言は 日付／イベント名 など決まった語を使う）。終了分は欄末尾の「過去のライブを見る」から新しい順に遡れる（初期20件＋「もっと見る」）。シートに残しておくだけでアーカイブになる。7列目にURLを入れると、その行に「詳しく見る」ボタンが出る。チケット販売ページや予約フォームなど任意のリンク先でよく、終了分にも出るのでアーカイブからライブレポートや動画へもリンクできる | スプレッドシート（ウェブに公開） |

`hero`、`youtube` は内容がめったに変わらないため、シートではなく CONFIG に直接書く形式です。`map` も基本は CONFIG ですが、住所・備考を運用側で直したい現場向けにシート指定（任意）も用意しています。`links` にも CONFIG 形式がありますが、連絡先やSNSを運用側で直したい現場ではシート版の `sheet-links` を使います。

```js
blocks: [
  { type: 'doc',         title: 'お知らせ', url: 'https://docs.google.com/document/d/e/…/pub' },
  { type: 'sheet-table', title: '料金表',   url: 'https://docs.google.com/spreadsheets/d/e/…/pub' },
]
```

独自の表示（曜日タブの番組表など）が要る場合は、`RENDERERS` に描画関数を1つ追加する形で拡張できます。

## 小規模店舗での構成例

```js
blocks: [
  { type: 'doc',          title: 'お知らせ',   url: '…' },  // 店主がドキュメントで自由に書く
  { type: 'sheet-menu',   title: 'メニュー',   url: '…' },  // 品名・価格・説明
  { type: 'sheet-hours',  title: '営業時間',   url: '…' },  // 曜日・時間・備考（今日を自動強調）
  { type: 'sheet-gallery',title: '写真',       url: '…' },  // 料理や店内の写真
  { type: 'map',          title: 'アクセス',   address: '沖縄県糸満市…', note: '駐車場あり' },
  { type: 'links',        title: 'お問い合わせ', items: [
    { label: '📞 電話する', url: 'tel:098-000-0000' },
    { label: 'Instagram',  url: 'https://www.instagram.com/…' },
  ]},
]
```

予約のような重い機能は作らず、外部サービスのページへのリンク（`links` ブロック）で逃がすのが前提です。更新頻度が低く、外部サービスの方が強い領域だからです。

## 個人制作映画の公式サイトでの構成例

```js
blocks: [
  { type: 'hero', image: '…', title: '映画タイトル', catch: 'キャッチコピー', date: '2026-12-05', dateLabel: '2026年12月5日（土）公開' },
  { type: 'youtube',         title: '予告編',           videoId: '…' },
  { type: 'doc',             title: 'あらすじ',         url: '…' },  // 監督がドキュメントで書く
  { type: 'sheet-screenings',title: '上映情報',         url: '…' },  // 終了分は自動で消える
  { type: 'sheet-quotes',    title: '推薦コメント',     url: '…' },
  { type: 'sheet-credits',   title: 'キャスト＆スタッフ', url: '…' },
  { type: 'sheet-gallery',   title: '場面写真',         url: '…' },
  { type: 'sheet-news',      title: 'ニュース',         url: '…' },
  { type: 'links',           title: 'チケット・SNS',   items: [ /* 劇場チケットページ、X、Instagram など */ ] },
]
```

個人制作映画は「上映形態が流動的（ミニシアター巡回、自主上映会の追加）」で「サイト係が専任でない」ことが多いため、更新がシートだけで完結する価値が特に大きい想定です。グッズ販売・配信は `links` で外部サービスへ逃がします。

## 想定する現場（対応ドメイン）

このパッケージが対象とするのは、次の4つの現場です。どれも「サイト係が専任でない」「更新は非技術者が行う」「高度な機能は要らない」という共通点があります。

| 現場 | 主なブロック構成 |
|---|---|
| 小規模個人店舗（飲食・雑貨・古着など） | `doc` / `alert`（お知らせ）、`sheet-menu`、`sheet-hours`、`sheet-gallery`、`map`、`links` |
| ライブハウス | `doc` / `alert`（お知らせ）、`sheet-events`（ライブ日程）、`sheet-table`（料金案内）、`map`、`links`（チケット予約は外部へ） |
| 自主制作映画 | `hero`、`youtube`、`doc`（あらすじ）、`sheet-screenings`、`sheet-quotes`、`sheet-credits`、`sheet-gallery`、`sheet-news`、`links` |
| コミュニティ放送 | 番組表の専用描画（`examples/fm-taman.html` が実例）、`alert`（災害情報）、`doc`（お知らせ）、SNSリンク |

この範囲を超える要件（EC、会員制、予約システム内製など）が出た時点で、このパッケージの担当外です。無理に広げず、外部サービスへつなぐか、別の道具を選ぶ判断をします。

## カスタマイズ

- 色や角丸は `<style>` 先頭の CSS変数（`--accent` など）で変更
- レイアウトは `.block` カードの積み重ねが基本。2カラム化などはCSS側で

## 注意点・限界（大事）

- **公開した内容は誰でも見られます。** 個人情報や社外秘は絶対に入れないでください。編集権限はGoogleアカウント側で管理されます
- 仕組み上、Googleの「ウェブに公開」エンドポイントに依存します。Google側の仕様変更で取得できなくなる可能性があります
- ドキュメントのスタイルは「ほぼ再現」であり、完全再現ではありません。フォント指定や大きな余白など、ドキュメント側の強い指定はページ側に寄せて調整しています
- スプレッドシート側はプレーンテキストのみです（セル色や太字は反映されません）
- アクセス解析やSEOを本気でやる用途、大規模サイトには向きません。「更新は楽に、作りは軽く」が目的の道具です
- 検索避けや限定公開はできません（見せたくないものは置かない、が原則）

## 実地テスト例

- `examples/fm-taman.html` — FMたまん番組表をSheetDoc CMS方式で再現したテスト版。独自レンダラー `timetable`（曜日タブ＋今日の曜日を自動表示、config行の適用期間を反映）を追加したもので、本番ページ（`workspace/user/files/index.html`）は置き換えていません。同じ公開CSVを使うため、シートを直せばこちらにも反映されます。お知らせ用ドキュメントURLは未設定のため、お知らせ欄は本番と同じく非表示です。
- `examples/livehouse.html` — ライブハウス特化のサンプル（架空の店舗「ライブハウス うみかじ」）。想定する現場のレシピどおり `alert`（緊急バナー）／`doc`（お知らせ）／`sheet-events`（ライブスケジュール）／`sheet-table`（料金案内）／`map`／`links` で構成し、ダークテーマに調整。サンプルなのでGoogleには接続せず、ファイル内のデモデータ（`demo:` URL）を表示します。実運用では CONFIG の `demo:` URL を「ウェブに公開」URLに差し替えるだけです。イベント表のサンプルは `samples/events.csv`、料金表は `samples/charges.csv`。すでにGoogleカレンダーでスケジュールを公開している現場向けに、カレンダー→イベント表シートへの取り込み用Apps Script（`examples/calendar_to_sheet.gs`）も同梱（APIキー不要。一度だけ実行して既存の予定をシートへ移行する使い方と、カレンダー運用を続ける場合の1時間ごとの自動取り込みの両対応）。

## 構成ファイル

- `index.html` — 本体（これ1枚で動作）
- `README.md` — この説明（制作者向け）
- `manual_owner.md` — 店主向けの更新マニュアル（専門用語なし）
- `samples/*.csv` — 表のサンプル（スプレッドシートにインポートして使う）。店舗向け：`menu` / `hours` / `gallery`、映画向け：`screenings` / `credits` / `quotes` / `news`、ライブハウス向け：`events` / `charges`（料金表）
